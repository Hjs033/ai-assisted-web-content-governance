# AI-Assisted Web Content Governance

A local, human-in-the-loop prototype for assessing representative web-content records and recording governance decisions.

## Project Objectives

The project explores how organizations can improve web content governance by:

- Integrating content management system (CMS) metadata and web analytics into content assessment.
- Evaluating content health using measurable indicators.
- Exploring AI-assisted qualitative analysis alongside quantitative assessment.
- Generating governance recommendations to support consistent content decisions.
- Preserving human decision authority over content-governance actions.
- Recording decisions and rationales to support traceability and accountability.

The current prototype implements selected objectives using representative data and deterministic analysis. Live CMS and analytics integrations and external large language model (LLM) evaluation remain future enhancements.

## Current Scope

The prototype combines a deterministic content-health score, rule-based qualitative observations, contextual recommendation rules, a Streamlit review interface, and SQLite audit-history persistence. It uses a representative 24-record CSV dataset; it is not connected to a production CMS or live analytics service.

The qualitative-analysis module is deliberately deterministic. Despite the project title, the evaluated version does **not** call an external LLM or require an OpenAI API key. The module can be replaced or extended later, subject to privacy, security, validation, and governance review.

## Implemented Capabilities

- Calculates a weighted health score from freshness, quality/completeness, performance, duplication/uniqueness, and engagement indicators.
- Produces preliminary recommendations using the current rules: Keep, Review, Update, or Consolidate. Retire is available as a human-selected final decision, but is not currently generated by the recommendation rules. The system does not execute lifecycle actions.
- Routes strategically critical `About` or `Organizational` content with low freshness to human review instead of treating age alone as an automatic update trigger.
- Provides deterministic qualitative observations based on available indicators.
- Presents assessment evidence and recommendations in a Streamlit interface.
- Allows a reviewer to record an independent assessment, a final decision, and a required rationale.
- Saves decisions in a local SQLite audit log, including criteria and prompt versions and a timestamp.
- Includes automated tests for assessment, qualitative-analysis, database, and selected application behaviors.

## Evaluation Dimensions

The prototype evaluates content using five dimensions:

- **Freshness:** How recently the content was updated.
- **Quality/completeness:** The completeness indicator available in the content record.
- **Performance:** The performance indicator available in the sample data.
- **Duplication/uniqueness:** The degree of similarity to other content.
- **Engagement:** The engagement indicator available in the sample data.

These dimensions contribute to the content-health score and help prioritize records for review. The resulting score is a decision-support indicator, not a definitive measure of content value or organizational importance.

## Human-in-the-Loop Process

The project is designed to keep content-governance decisions under human control. The intended workflow is:

1. The system presents available content evidence.
2. The reviewer independently assesses the content.
3. The system presents its assessment and preliminary recommendation.
4. The reviewer compares the independent assessment with the system's results.
5. The reviewer records a final decision.
6. The system saves the decision and rationale in the local audit log.

The prototype supports assessment review and decision recording. The exact workflow depends on the capabilities implemented in the application, and the local audit log is not a production-grade security or compliance control.

## Important Boundaries

- The CSV contains representative sample data, not a validated production content inventory.
- CMS metadata and analytics are represented by sample fields; no live integrations are implemented.
- Qualitative observations are rule-based, not generated by an external LLM.
- Human review is required. The application does not publish, update, consolidate, or retire production content.
- Local SQLite persistence is a prototype audit mechanism, not a production-grade security or compliance control.
- Automated test coverage does not establish production readiness. Accessibility, security, concurrency, backup/recovery, formal user acceptance, and deployment validation remain future work.

## Setup

Python 3.11 or later is recommended.

From the repository root, create and activate a virtual environment, then install dependencies:

```bash
python -m venv .venv
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
# macOS/Linux
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt
```

Run the application from the repository root:

```bash
streamlit run src/app.py
```

The local database is created at `data/governance.db` when the application initializes. It is ignored by Git and should be treated as local prototype data.

## Tests

Run the full suite from the repository root:

```bash
python -m pytest -q
python -m pytest --cov=src --cov-report=term-missing
```

The application tests require Streamlit to be installed from `requirements.txt`. Report test counts and coverage only from the actual run being documented. Statement coverage measures executed statements; it does not prove all branches, inputs, or system-level qualities are correct.

## Version control

- `development` is the working branch for changes.
- `main` is the stable branch for reviewed milestones.
- Commit related source, tests, and documentation together where practical.
- Run the test suite and review the diff before merging.
- Do not commit secrets, local databases, virtual environments, or unauthorized data.
